# مرجع — أداة تحقق ومعرفة للمعرّفين بالإسلام

MVP جاهز ومُختبر لمسار "أدوات المعرفة والتحقق للمعرّفين بالإسلام" — وحدتان رئيسيتان:
1. **البحث الموثوق السريع** — بحث دلالي عربي (مطابقة لفظية + جذر الكلمة + مرادفات، فوق TF-IDF) في قاعدة مصادر موثقة، مع تصنيف قوة كل دليل. مثال: البحث عن "الصابرين" يلتقط نصوصاً تحتوي "صبر/يصبر/صابر" لأن المحرك يُرجع الكلمات لجذرها ويوحّد صيغها قبل المطابقة.
2. **لوحة المصادر** — تفعيل/تعطيل أي مجموعة مصدر مباشرة، لإظهار شفافية النظام (لا "يخترع" من مصدر معطّل) وأثر ذلك فوراً على نتائج البحث.

بالإضافة لطبقة اختيارية (RAG كامل): AI يصوغ إجابة موجزة **مقيّدة حصراً بالمصادر المسترجعة**، مع الامتناع الصريح إن لم تكن المصادر كافية.

**قاعدة المصادر الحالية:** 10,558 نصاً حقيقياً بالكامل — **القرآن الكريم كاملاً** (6,236 آية) + **4,322 حديثاً** من 17 كتاباً (مستوردة من قاعدة hadith-json). **لا يحتوي المشروع على فتاوى فقهية** . مُختبر بالكامل عبر `backend/test_e2e.py`. **اقرأ التنبيهين بقسم "3.أ" أدناه قبل التسليم — خصوصاً بخصوص الترخيص وغياب التخريج الفعلي لكل حديث.**

---

## 1. التشغيل السريع (سيرفر واحد فقط، بدون أي مفاتيح API)

المشروع الآن **سيرفر واحد** يخدم الواجهة والـ API معاً من نفس المنفذ — لا اعتماد على `localhost` بعنوان ثابت، ولا حاجة لتشغيل سيرفر ثانٍ للواجهة. هذا يسمح بمشاركة المشروع لتجربته على أي جهاز أو استضافة بدون أي تعديل بالكود.

```bash
cd backend
pip install -r requirements.txt
python3 app.py
```

افتح المتصفح على الرابط المطبوع (`http://127.0.0.1:5050` محلياً، أو عنوان الاستضافة إن نُشر). الواجهة تستخدم مسارات نسبية (`API_BASE = ""`) فتعمل تلقائياً على أي منفذ أو نطاق — بما فيها تشغيله على منفذ مختلف عبر متغير البيئة `PORT`:

```bash
PORT=8080 python3 app.py
```

النظام يعمل بالكامل بدون إنترنت أو مفاتيح API — البحث الدلالي وتصنيف قوة الدليل كلها منطق محلي مُختبر. فقط ميزة "الصياغة الذكية" الاختيارية تحتاج مفتاح Gemini API.

## 2. تفعيل الصياغة الذكية (اختياري)

```bash
cp .env.example .env
# عدّل .env وضع مفتاح Gemini الحقيقي
python3 backend/app.py
```

فعّل مربع "صِغ إجابة موجزة بالذكاء الاصطناعي" في واجهة البحث. بدون المفتاح، تظهر المصادر مباشرة دون صياغة (fallback آمن، لا يتعطل أي شيء). النموذج الافتراضي هو `gemini-3.8-flash` ويمكن تغييره عبر `GEMINI_MODEL`.

## 3. توسيع المشروع قبل التسليم —

### أ. مصدرا المشروع الأساسيان (مُستوردان فعلياً بالكامل)

المشروع يعتمد حصراً على مصدرين حقيقيين :

1. **القرآن الكريم كاملاً** (6,236 آية) — مستورد من ملف `quran_ready.json` عبر `backend/importers/import_quran_ready.py`
2. **الحديث** (4,322 حديثاً من 17 كتاباً، بالسند الكامل) — مستورد من قاعدة **hadith-json** عبر `backend/importers/import_local_hadith_json.py`

لإعادة الاستيراد أو التوسعة:
```bash
cd backend/importers

# القرآن الكامل (يستبدل أي نسخة قديمة تلقائياً، لا تكرار)
python3 import_quran_ready.py --source-file /path/to/quran_ready.json

# الحديث (بدون حد = كل الـ 50,884 حديثاً، أو حدد --limit)
python3 import_local_hadith_json.py --source-dir /path/to/hadith-json-main --limit 0
```

### ب. توسيع قاعدة المصادر بمصادر أخرى (سكربت إضافي يتصل بالإنترنت)

بدل إدخال النصوص يدوياً، يوجد `backend/importers/import_open_sources.py` يتصل فعلياً بمصادر مفتوحة الترخيص ويحوّل بياناتها لصيغة `corpus.json` تلقائياً:

| المصدر | API المستخدم | الترخيص | يحتاج مفتاح؟ |
|---|---|---|---|
| القرآن الكريم | `api.alquran.cloud` (نص Tanzil الرسمي) | CC BY 3.0 | لا |
| الحديث (الكتب التسعة) | `fawazahmed0/hadith-api` عبر jsDelivr | مفتوح | لا |

```bash
cd backend/importers

# استيراد سور معينة من القرآن
python3 import_open_sources.py --quran-surahs 1 112 113 114

# استيراد أحاديث من البخاري ومسلم (أول 100 حديث من كل كتاب)
python3 import_open_sources.py --hadith-editions ara-bukhari ara-muslim --hadith-limit 100

# الاثنين معاً
python3 import_open_sources.py --quran-surahs 1 2 --hadith-editions ara-bukhari ara-tirmidhi --hadith-limit 200
```

السكربت يدمج البيانات الجديدة في `corpus.json` الحالي (بدون تكرار عند إعادة التشغيل) ويسجّل أي مصدر جديد تلقائياً في `sources.json` (يظهر فوراً بلوحة المصادر بالواجهة).

**⚠️ تنبيه مهم حول درجة الحديث:** دالة `classify_grade()` بالسكربت تبسيط عملي للـ MVP — تعتمد على حقل `grades` إن وُجد بالنسخة العربية، أو تفترض افتراضاً عاماً لكتب الصحيحين. **قبل التسليم النهائي، تحقق يدوياً من درجة أي حديث حسّاس** من مصدر متخصص في التخريج (كالدرر السنية) قبل الاعتماد عليه في العرض.

**مصادر أخرى ذكرها الفريق (الدرر السنية، الشاملة):**
- **الدرر السنية**: يوجد مشروع مجتمعي (`dorar-hadith-api` على GitHub) يوفر واجهة JSON نظيفة فوقه.

### ج. توسيع قاعدة المصادر يدوياً (بديل)
لو تبي تضيف نصوصاً يدوياً بدل الاستيراد الآلي، أضفها بنفس بنية `backend/data/corpus.json`:
```json
{
  "id": "معرّف_فريد",
  "type": "quran | hadith",
  "text": "النص الكامل",
  "source_ref": "المرجع الدقيق (سورة/آية أو كتاب/رقم حديث)",
  "topic": "الموضوع",
  "evidence_strength": "وصف نصي يُستخدم في التصنيف التلقائي",
  "confidence_score": 0.0 إلى 1.0
}
```

### د. البحث الدلالي العربي — كيف يعمل وكيف يُطوَّر أكثر
`retrieval.py` يطبّق طبقة دلالية خفيفة بدون مكتبات ML خارجية: تطبيع النص العربي (حذف التشكيل، توحيد صيغ الألف/الهمزة) ثم تجذيع خفيف (حذف سوابق/لواحق شائعة) ثم قاموس مرادفات (صيام/صوم، صلاة، زكاة/صدقة، حج، جهاد، نية، توبة، صبر، رحمة، عدل، كذب/صدق...) يوحّد الصيغ المختلفة لجذر واحد قبل حساب التطابق (TF-IDF + cosine similarity). هذا يلتقط صيغاً لغوية مختلفة عن النص الأصلي (مثل "الصابرين" ↔ "صبر") بدون حاجة لنموذج embeddings ثقيل.

للارتقاء لدقة أعلى (اختياري): استبدل هذه الطبقة بمكتبة embeddings حقيقية (`sentence-transformers` بنموذج عربي، أو Claude/OpenAI embeddings + قاعدة متجهات مثل Chroma) — الواجهة الخارجية لدالة `search()` تبقى كما هي، فلن تحتاج تعديل باقي الملفات.

### هـ. الأمان والخصوصية
 بيانات `corpus.json` نصوص دينية عامة، وهذا مسموح.

## 4. هيكل المشروع

```
islamic-verify-tool/
├── backend/
│   ├── app.py                   # سيرفر واحد: يخدم الواجهة (static/) + REST API معاً
│   ├── retrieval.py              # محرك البحث: TF-IDF + بحث دلالي عربي (تجذيع + مرادفات) + إدارة تفعيل المصادر
│   ├── evidence_classifier.py    # تصنيف قوة الدليل بقواعد صريحة
│   ├── llm_client.py             # طبقة RAG: صياغة إجابة مقيّدة بالمصادر
│   ├── importers/
│   │   ├── import_open_sources.py       # استيراد من alquran.cloud + hadith-api (إنترنت، اختياري)
│   │   ├── import_local_hadith_json.py  # استيراد الحديث من قاعدة hadith-json المحلية
│   │   └── import_quran_ready.py         # استيراد القرآن الكامل من quran_ready.json
│   ├── test_e2e.py               # اختبار شامل لكل نقاط الاتصال
│   ├── static/
│   │   └── index.html            # الواجهة (وحدتان: البحث الموثوق / لوحة المصادر) — تُخدم من نفس سيرفر الـ API
│   ├── data/
│   │   ├── corpus.json           # قاعدة المصادر (10,558 نصاً: قرآن + حديث)
│   │   └── sources.json          # لوحة تفعيل/تعطيل مجموعات المصادر
│   └── requirements.txt
├── .env.example
└── README.md
```

## 5. نقاط الاتصال (API Endpoints)

| Endpoint | الوظيفة |
|---|---|
| `GET /` | يخدم الواجهة الأمامية (نفس السيرفر والمنفذ) |
| `GET /api/health` | فحص الاتصال وعدد المصادر |
| `POST /api/search` | بحث موثق دلالي `{query, top_k?, synthesize?}` — يرجع أيضاً `sources_searched` (قائمة كل المصادر المفعّلة مع تحديد أيها تطابق) |
| `GET /api/sources` | لوحة المصادر: عرض كل مجموعة مصدر وحالتها |
| `POST /api/sources/toggle` | تفعيل/تعطيل مجموعة مصدر `{source_id, enabled}` |
